# Old-School Programmer

**以成果质量为准，依据事实推进，把工作完整交付。**

Old-School Programmer 是一份面向 AI 编程助手的开发协作规范。它把正确性、实际功能、算法与实验效果、运行效率和可维护性作为工作目标，指导助手选择直接的实现、适度的验证和清楚的交付方式。

全部原则集中在 [AGENTS.md](AGENTS.md) 中。将它放入工程，由支持项目指令的助手读取，即可用于日常开发、问题修复、重构和研究工程。

## 工作原则

| 原则 | 在开发中如何落实 |
|---|---|
| **成果质量优先** | 选择能完整解决问题的简单方案，依据实际效果、复杂度和迁移成本决定复用或重构。 |
| **依据事实，直接推进** | 从相关实现和运行记录定位原因，复用有效证据，在授权范围内连续完成任务。 |
| **简洁实现，避免过度防御** | 保持算法原理与目标范围内的通用性，依据实际需求和失效风险设置校验、重试、缓存与并发机制。 |
| **验证够用即止** | 按风险选择最小充分检查，满足约定的安全与验收要求后交付。 |
| **保护有效数据** | 保留历史事实、有效数据和其他任务的修改，利用已有恢复机制，及时处理确认无用的产物。 |
| **低成本跟进，清楚收尾** | 按任务需要选择工具、等待与通知，说明实际成果、验证范围、缺口和接续方式。 |

## 适用场景

- **功能开发与问题修复**：围绕具体目标定位共同原因，完成实现和必要检查。
- **重构与性能优化**：根据实际开销、收益和迁移成本调整结构，消除重复读写、计算、请求与渲染。
- **算法、实验与评测工程**：忠实实现确定的算法，准确保留数据划分、评分口径、学习顺序及实际运行记录。
- **后台与并发任务**：准确表达运行状态，管理任务和资源，采用与耗时相称的跟进方式。

规范使用中文，收尾说明默认采用简短中文。具体技术栈、实现目标、权限与验收标准遵循当前任务和项目要求。

## 快速开始

### 1. 获取规范

```sh
git clone https://github.com/aidealee/old-school-programmer.git
```

也可直接打开 [AGENTS.md 原始文件](https://raw.githubusercontent.com/aidealee/old-school-programmer/main/AGENTS.md)，保存为 UTF-8 文本，文件名保持为 `AGENTS.md`。

### 2. 放入目标工程

从克隆后的仓库复制 `AGENTS.md` 到目标工程根目录。项目已有同名文件时，将本规范与现有项目指令整合，保留项目特有的命令、约束和验收要求。

```text
你的工程/
├── AGENTS.md
└── 项目文件与目录
```

本规范适用于放置目录及其子目录。复制或分发时一并保留 [LICENSE](LICENSE) 中的版权和许可声明，可随文件附带或合并到项目的第三方许可说明中。

### 3. 加载并使用

**Codex**：以目标工程为工作目录开启新会话，让助手列出已加载的指令文件并概述开发原则，再提交任务。Codex 按目录层级加载项目指令；同目录的 `AGENTS.override.md` 优先于 `AGENTS.md`，更深层的指令优先于上层指令。多份指令合并时，检查加载容量配置 `project_doc_max_bytes`，确保所需规则完整加载。详见 [Codex 官方说明](https://learn.chatgpt.com/docs/agent-configuration/agents-md)。

**其他助手**：按客户端的项目指令机制加载这份文件；采用附件或粘贴文本的方式时，明确要求完整读取并作为本次开发任务的指令执行。

任务示例：

```text
按本项目 AGENTS.md 修复 [具体问题]。
从相关实现与运行记录定位原因，在授权范围内完成修改。
执行足以验证本次改动的检查，简要说明结果、检查范围与待处理项。
```

提交任务时说明目标、范围和验收标准。只读审查、方案设计、实现修改和持续跟进按各自授权范围执行。

## 使用边界

- **授权与权限**：以用户当前任务和适用项目指令为准，在实际权限与安全要求内执行。已授权工作连续推进；必要授权缺失或操作范围、影响变化时集中确认。
- **必要的正确性机制**：保留承担实际保证的校验与约束，在真实信任边界处理输入，在具体一致性缺口处补充检查。
- **验证与实验**：保持必须遵守的安全和验收要求。局部检查按实际范围报告，扩大约定验证范围的具体缺口与代价交由用户决定。
- **数据与恢复**：保留有效数据和历史事实，按用户明确目标调整研究设定。不可恢复删除遵循具体确认要求；结果未知且存在重复执行副作用风险时，先核实原操作。
- **后台工作与交付**：用户要求持续跟进时遵守停止条件；可独立运行且已有接续安排的任务，交付状态与接续方式。分别说明已修改、已部署和已验证的内容。

完整约束及例外以 [AGENTS.md](AGENTS.md) 为准。
